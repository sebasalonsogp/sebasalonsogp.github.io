# Content model

All visible facts live in content files. Components and scenes read them; adding or removing
a project, role or skill never requires code changes. Everything is validated at build time
with Zod schemas in `src/content.config.ts`.

## Projects — `src/content/projects/<id>.md`

The filename is the stable id and the URL (`/projects/<id>/`). Do not rename a published id
without a redirect plan.

```yaml
---
title: Eigenflow
short: Eigenflow # planet label
summary: Shows how one weak link in a network slows everything down, using the graph Laplacian.
domain: ml # backend | ml | data | math  → planet surface
repo: sebasalonsogp/eigenflow # orbit + size come from src/data/github.json
demoUrl: https://eigenflow-8tdq.onrender.com # optional; present = ring + "Land" action
subsystems: [FastAPI numerical API, React + D3 client] # moons; [] for none
tech: [Python, FastAPI, NumPy, React, TypeScript, D3, Docker]
brief: Inject heat into a network and watch it spread. …
log: FastAPI and NumPy build L = D − A, … 57 backend tests at 99% line coverage …
media:
  - { type: video, src: eigenflow-demo.webm, poster: eigenflow-poster.jpg, caption: Demo recording }
  - { type: image, src: eigenflow-experiment.jpg, caption: The bottleneck experiment }
  - {
      type: image,
      src: eigenflow-fiedler.jpg,
      caption: Fiedler partition and spectrum,
      fit: contain,
    }
tour: 1 # optional position in the 60-second tour
draft: false
---
Optional long-form write-up for the project page.
```

Rules: `brief` is plain language for anyone; `log` is for engineers. Only real numbers from
the repository. Prototype media must say so in the caption. Images live in
`src/assets/projects/<id>/` (optimized by `astro:assets`); videos in `public/media/<id>/`.
Until the files are copied in (see `docs/handoff.md`), `media` entries hold validated file
names only and nothing renders them.

Projects are ordered by `lastCommit` (newest first, ties broken by id); that order drives the
orbits. `tour` positions must be unique. Read projects through `getProjects()` in
`src/lib/content.ts`, which joins the GitHub snapshot and applies these rules.

## GitHub snapshot — `src/data/github.json`

```json
{ "sebasalonsogp/eigenflow": { "lastCommit": "2026-09-13", "loc": 7291 } }
```

Generated by `scripts/sync-github` (Phase 8 automates it); committed so builds are
deterministic. A project missing from the snapshot fails the build. Validated by
`src/lib/github-snapshot.ts`. The current values were entered by hand from the concept
(October 2026) until the sync script exists.

## Experience — `src/content/experience/<id>.yaml`

```yaml
title: Founding Software Engineer
org: PadStats
orgShort: PadStats
place: Miami, FL (hybrid)
lane: eng # research | data | eng | lead
start: 2025-06
end: 2026-06 # omit for current
highlight: true # accent color on the timeline
label: Founding software engineer
sublabel: PADSTATS · JUN 2025 – JUN 2026
note: Work that started during the internship and carried into the full-time role.
bullets: […]
skills: [Python, FastAPI, GCP, …]
link: { label: Research code, url: https://… } # optional
```

`orgShort` is the short org name used in skill cross-links. `sublabel` is written in
capitals as displayed. Dates are `YYYY-MM`; `end` must not precede `start`.

Roles currently: CISA intern, UM ML research assistant, Kappa Theta Pi director, Bonsai
analyst, Bonsai project manager, PadStats software engineering intern, PadStats founding
software engineer.

## Education — `src/content/education/um.yaml`

School, place, degrees, minor, honors, GPA (string, e.g. `'3.84'`), start/end (`YYYY-MM`),
`label`/`sublabel` (the two-line band caption, in capitals) and coursework. Shown as the
timeline's college band and in the readable experience list.

## Skills groups — `src/data/skill-groups.ts`

Group names and member skills for the constellation (Machine learning, Backend & web,
Scientific Python, Data, Cloud, Leadership) plus the core skill (Python). The set of skills
itself is derived from project `tech` and role `skills`; a skill missing from every group
fails the build (the schemas only accept grouped skill names), and so does a skill listed in
two groups.

## Site profile — `src/data/site.ts`

Name, eyebrow, pitch (lead + emphasized phrase), lede, availability line, email, phone (with
a `showPhone` flag), location, LinkedIn and GitHub (url + display handle), resume file name
(served from `public/`), earlier-work repositories (name, url, year). Validated with Zod
when the module loads, so a bad value fails the build.
